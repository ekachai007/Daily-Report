# SiteLog — ระบบรายงานประจำวันงานก่อสร้าง

เว็บแอปสำหรับบันทึก **รายงานประจำวัน (Daily Report)** ของหน่วยงานก่อสร้าง
เขียนด้วย Flask ในไฟล์เดียว (`app.py`) ใช้ SQLite เก็บข้อมูล และใช้ Tailwind CSS ผ่าน CDN

## สิ่งที่ต้องมี

- Python 3.9 ขึ้นไป
- Flask 3.x
- อินเทอร์เน็ต (ใช้โหลด Tailwind CSS และฟอนต์ Noto Sans Thai จาก CDN)

## การติดตั้งและรัน

1. ติดตั้ง Flask

   ```bash
   pip install flask
   ```

2. รันแอป

   ```bash
   python app.py
   ```

3. เปิดเบราว์เซอร์ไปที่ <http://127.0.0.1:5000>

ครั้งแรกที่รัน แอปจะสร้างไฟล์ฐานข้อมูล `construction_reports.db` ไว้ในโฟลเดอร์เดียวกับ `app.py`
และใส่รายงานตัวอย่างให้ 3 ฉบับ ถ้าไม่ต้องการข้อมูลตัวอย่าง ให้ลบรายงานเหล่านั้นทิ้งได้จากหน้าเว็บ

> ถ้าต้องการเริ่มใหม่ทั้งหมด ให้ปิดแอปแล้วลบไฟล์ `construction_reports.db` ทิ้ง
> เมื่อรันใหม่ แอปจะสร้างฐานข้อมูลพร้อมข้อมูลตัวอย่างให้อีกครั้ง

## วิธีใช้งาน

### 1. หน้าภาพรวม (`/`)

- **การ์ดสรุป:** จำนวนรายงานทั้งหมด, รายงานเดือนนี้, แรงงานเฉลี่ยต่อวัน และอุบัติเหตุสะสม
- **ความคืบหน้าโครงการ:** แถบเปอร์เซ็นต์ของแต่ละโครงการ อิงจากรายงานฉบับล่าสุดของโครงการนั้น
  คลิกชื่อโครงการเพื่อกรองเฉพาะรายงานของโครงการนั้น
- **ค้นหาและกรอง:** ค้นจากชื่อโครงการ ผู้รายงาน รายละเอียดงาน หรือปัญหา
  และกรองตามโครงการ สถานะ และช่วงวันที่ได้
- **ตารางรายงาน:** คลิกแถวใดก็ได้เพื่อเปิดดูรายละเอียด
  ถ้าวันนั้นมีอุบัติเหตุ จะมีสัญลักษณ์ ⚠ แสดงต่อจากไอคอนสภาพอากาศ

### 2. สร้างรายงานใหม่

กดปุ่ม **+ สร้างรายงาน** มุมขวาบน แล้วกรอกข้อมูลตามหัวข้อ

| หัวข้อ | รายละเอียด |
|---|---|
| ข้อมูลทั่วไป | ชื่อโครงการ\*, วันที่\*, ผู้รายงาน\*, เวลาเริ่ม/เลิกงาน, สภาพอากาศเช้า/บ่าย, ความคืบหน้าสะสม (%), สถานะ |
| รายละเอียดงาน | งานที่ทำวันนี้\*, แผนงานวันถัดไป, ปัญหา/อุปสรรค |
| แรงงาน | ประเภทช่างและจำนวนคน (แอปรวมยอดให้อัตโนมัติ) |
| เครื่องจักร / อุปกรณ์ | รายการ จำนวน และสถานะ (ใช้งาน / สแตนด์บาย / ชำรุด-ซ่อม) |
| วัสดุ | รายการ จำนวน และหน่วย |
| ความปลอดภัย | จำนวนอุบัติเหตุ และบันทึกด้านความปลอดภัย |

\* = ต้องกรอก

เคล็ดลับ:

- กด **+ เพิ่มแถว** เพื่อเพิ่มรายการ หรือกด **✕** เพื่อลบแถว
- แถวที่ไม่ได้กรอกชื่อรายการจะไม่ถูกบันทึก จึงเว้นแถวว่างไว้ได้
- ช่องชื่อโครงการและประเภทช่างมีรายการให้เลือก (autocomplete) จากข้อมูลที่เคยกรอก
- ในช่องข้อความ ขึ้นบรรทัดใหม่ได้ตามปกติ และหน้ารายละเอียดจะแสดงตามบรรทัดที่พิมพ์

### 3. ดูรายละเอียดรายงาน

หน้านี้แสดงข้อมูลทั้งหมดของรายงาน และมีปุ่มจัดการดังนี้

- **แก้ไข:** เปิดฟอร์มเพื่อแก้ไขข้อมูล
- **คัดลอกเป็นวันใหม่:** สร้างรายงานของวันนี้โดยดึงข้อมูลจากรายงานนี้มาใช้ ได้แก่
  โครงการ ผู้รายงาน เวลาทำงาน ความคืบหน้า แรงงาน เครื่องจักร และวัสดุ
  และนำ "แผนงานวันถัดไป" ของรายงานเดิมมาใส่เป็น "งานที่ทำวันนี้" ให้แก้ไขต่อได้เลย
- **พิมพ์ / PDF:** สั่งพิมพ์ หรือเลือก "Save as PDF" ในหน้าต่างพิมพ์ของเบราว์เซอร์
  ตอนพิมพ์จะซ่อนเมนูและปุ่มต่าง ๆ และเพิ่มช่องลงนามของผู้รายงานกับผู้ตรวจสอบ
- **เปลี่ยนสถานะ:** ฉบับร่าง → ส่งแล้ว → อนุมัติแล้ว
- **ลบรายงาน:** มีหน้าต่างให้ยืนยันก่อนลบ และลบแล้วกู้คืนไม่ได้

### 4. ส่งออก CSV

ที่หน้าภาพรวม กด **ส่งออก CSV** เพื่อดาวน์โหลดไฟล์ `daily_reports.csv`
ไฟล์จะมีเฉพาะรายงานที่ตรงกับตัวกรองที่เลือกอยู่ และเปิดด้วย Excel แล้วภาษาไทยแสดงถูกต้อง

## หน้าเว็บทั้งหมด (Routes)

| Method | Path | หน้าที่ |
|---|---|---|
| GET | `/` | หน้าภาพรวมและรายการรายงาน (รองรับ `q`, `project`, `status`, `date_from`, `date_to`) |
| GET, POST | `/reports/new` | สร้างรายงาน (`?copy=<id>` = คัดลอกจากรายงานเดิม) |
| GET | `/reports/<id>` | ดูรายละเอียดรายงาน |
| GET, POST | `/reports/<id>/edit` | แก้ไขรายงาน |
| POST | `/reports/<id>/status` | เปลี่ยนสถานะรายงาน |
| POST | `/reports/<id>/delete` | ลบรายงาน |
| GET | `/export.csv` | ส่งออก CSV (ใช้ตัวกรองเดียวกับหน้าภาพรวม) |

## โครงสร้างไฟล์

```
app.py                     # โค้ดทั้งหมด: routes, ฐานข้อมูล และ templates (Jinja + Tailwind)
construction_reports.db    # ฐานข้อมูล SQLite (สร้างอัตโนมัติเมื่อรันครั้งแรก)
README.md
```

ข้อมูลแรงงาน เครื่องจักร และวัสดุ เก็บเป็น JSON ในคอลัมน์ `labor`, `equipment` และ `materials`
ของตาราง `reports`

## การปรับแต่ง

ค่าที่แก้ได้อยู่ในส่วน "ค่าคงที่" ตอนต้นของ `app.py`

- `WEATHER`: ตัวเลือกสภาพอากาศและไอคอน
- `EQUIPMENT_STATUS`: ตัวเลือกสถานะเครื่องจักร
- `STATUSES`: ชื่อสถานะของรายงานและสีของป้ายสถานะ
- รายการประเภทช่างที่แนะนำ อยู่ใน `<datalist id="trade-list">` ของ template `form.html`

## ก่อนนำไปใช้งานจริง

`python app.py` รันในโหมด debug ซึ่งเหมาะกับการพัฒนาเท่านั้น ถ้าจะใช้งานจริงควรทำดังนี้

1. ตั้งค่า `SECRET_KEY` เป็นค่าสุ่มที่เดาไม่ได้ผ่าน environment variable
2. รันด้วย WSGI server แทน `app.run(debug=True)` เช่น
   - Windows: `pip install waitress` แล้วรัน `waitress-serve --port=5000 app:app`
   - Linux: `pip install gunicorn` แล้วรัน `gunicorn -w 2 -b 0.0.0.0:5000 app:app`
3. สำรองไฟล์ `construction_reports.db` เป็นประจำ

นอกจากนี้ แอปยังไม่มีระบบล็อกอิน ทุกคนที่เข้าถึง URL ได้จะดู แก้ไข และลบรายงานได้ทั้งหมด
ถ้าจะเปิดให้ใช้งานผ่านเครือข่าย ควรเพิ่มระบบยืนยันตัวตนก่อน
